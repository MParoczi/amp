# Phase 03 — leaner runs: Implementation Plan

> Executed by amp:build (one amp:implementer per task, reviewed per task). Checkbox steps track progress.

**Goal:** Faster, cheaper amp runs with unchanged quality gates (spec D1–D10).
**Spec:** docs/amp/specs/2026-11-01-03-leaner-runs.md, the binding authority; conflicts resolve against it.
**Branch:** framework/03-leaner-runs
**Architecture:** All behavior is Markdown in `src/` rendered by `scripts/render` into `skills/`, `agents/` (Claude Code) and `codex/` (Codex); `{{claude: …}}`/`{{codex: …}}` spans and `<!-- claude -->`/`<!-- codex -->` blocks split per tool. `scripts/test` pins strings in the rendered trees.
**Tech stack:** bash, awk, Markdown; TypeScript hook module `hooks/register.tsx` (help text only).
**Dispatch skills:** none.

## Global Constraints
- Edit only `src/` for skills and agents, then run `bash scripts/render` and commit the rendered `skills/`, `agents/`, `codex/` changes in the same commit. Never hand-edit rendered trees.
- Each task's gate: `bash scripts/test` passes and `bash scripts/render --check` is clean.
- Claude-only words (SendMessage, `/amp-models`, `${CLAUDE_PLUGIN_ROOT}`, `user_config`, Skill tool) must not reach `codex/`; Codex-only words (`spawn_agent`, `followup_task`, `wait_agent`, `AGENTS.md`) must not reach `skills/` or `agents/` (existing `leaks` case). Use the span/block markup.
- Keep amp's prose voice: short declarative sentences, no new headings unless a section is new.
- New tests go into `scripts/test` as new `case=` blocks using the existing `holds`/`lacks` helpers.

## Review Focus
1. A resumed reviewer widening scope in a re-review (blocking on things outside the fix diff). — Task 3
2. Pipelining: N+1 committed into the main tree or BASE computed wrong. — Task 5
3. A leftover worktree/temp branch after a drop or crash. — Task 5
4. Lean rules lost in transit to implementer/reviewer, or a prompt still pointing an agent at `amp:lean`. — Task 1
5. Codex/Claude leakage after edits. — every task (existing `leaks` case)
