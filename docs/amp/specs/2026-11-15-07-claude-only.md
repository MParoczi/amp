# Phase 07 — Claude Code only: Spec

## 1. Goal

Phase 07 (`framework/07-claude-only`) removes Codex support from amp and makes Claude Code the only
target. The Codex trees, installer, hooks port and manifest go; so does the `src/` → rendered-tree
pipeline, which existed only to produce two trees. `skills/` and `agents/` become the files edited
directly. Two small Claude-only improvements ride along: the `/amp-run` pane shows which steps a
run has off, and skills name Claude Code's tools where they spoke generically. Release 2.0.0.

The request was a plain one; this repo has no roadmap, so the phase id follows the specs before it.
A second run, 08, adds `/amp-steps` and replaces the status line; it is out of scope here.

## 3. Architecture

After this phase the repository layout is: `.claude-plugin/` (manifest, marketplace), `skills/`,
`agents/`, `hooks/`, `scripts/test`, `docs/`, `README.md`, `CHANGELOG.md`. There is no build step:
what is committed under `skills/` and `agents/` is what Claude Code loads.

Because the committed `skills/` and `agents/` already equal the Claude render (S2), the conversion
is deletion, not regeneration: no file under `skills/` or `agents/` changes because of the pipeline
removal. They change only for §5.3 (wording) and the one `src/` path mention.

## 5. Interfaces

### 5.1 `scripts/test` after the change

- Usage and output contract unchanged: `bash scripts/test`, one `ok: <case>` line per case, the
  first failure prints `FAIL: <case>: <detail>` and exits 1.
- Kept cases, with every `codex/…` path and Codex-only assertion removed and every
  `for t in skills codex/skills` loop reduced to `skills`: `modes`, `manifests`, `claude-mechanics`,
  `lean-in-agents`, `effort`, `reviewer-resume`, `routing-once`, `depends`, `parallel`,
  `steps-off`, `stage-lines`, `alert-wav`. An assertion that held a Codex-only phrase in a
  `codex/…` file is dropped; one that held a phrase in both trees keeps its `skills/…` half.
- `modes`: `git ls-files -s -- scripts/test 'skills/build/scripts/*'` lists only mode `100755`
  entries (the `codex/`, `src/`, `scripts/render` and `amp-hook` parts go).
- `holds`/`lacks` are defined before the first case that uses them.
- `manifests`: asserts `"version": "2.0.0"` in `.claude-plugin/plugin.json`, that the description
  does not contain `Codex`, and that `.codex-plugin` does not exist.
- New case `claude-only`:
  - none of `codex`, `.codex-plugin`, `src`, `scripts/render` exists;
  - `git grep -n -i -e codex -e 'AGENTS\.md' -e '{{' -e '<!-- claude' -e spawn_agent -e request_user_input -e wait_agent -e '\$amp:' -e 'amp-<role>' -- skills agents hooks .claude-plugin`
    prints nothing (this keeps what the deleted `leaks` case asserted for the Claude tree);
  - `git grep -n -i codex -- README.md` prints nothing;
  - "prints nothing" is tested as `out=$(git grep … || true)` followed by an emptiness check,
    because `git grep` exits 1 on no match and the script runs under `set -e`;
  - `git grep -n 'src/agents\|src/skills' -- skills agents hooks` prints nothing.

### 5.2 `/amp-run` shows steps off

- `hooks/run.ts`: `Run` gains `off?: string[]`. A ledger line `Off: <names joined by ", ">` sets it
  to the names and `Off: none` sets it to `[]`; the last `Off:` line wins. A ledger without the
  line leaves `off` undefined (the field is `off?: string[]`): a standalone amp:build ledger has
  no such line and the `CLAUDE.md` table applies there.
- `hooks/register.tsx` `runLines`: after the `Parallel:` line, a line
  `Steps off: <names joined by ", ">`; `Steps off: none` for `[]`; and
  `Steps off: not recorded (the CLAUDE.md table applies)` when `off` is undefined.
- `statusText` and `resumeText` are unchanged.

### 5.3 Wording for Claude Code's tools

- `skills/build/SKILL.md`, Setup step 3: "Create one todo per task." becomes "Create one task per
  plan task in the session's task list (TaskCreate, or TodoWrite where that is the tool)."
- `skills/lean/SKILL.md:16`: `src/agents/implementer.md` becomes `agents/implementer.md`.
- `skills/ship/SKILL.md`, step 4: "Run it in the background (or with a long timeout) and wait for
  completion rather than polling in short loops." becomes "Run it with the Bash tool's
  `run_in_background` and wait for the completion notification; never poll in short loops."
- Nothing else is generic: amp:grill already names AskUserQuestion, and the re-review and
  confirmation paths already name SendMessage.

### 5.4 Release

- `.claude-plugin/plugin.json`: `"version": "2.0.0"`; description
  `amp: a grill-first, autonomous workflow for Claude Code. Interview once, then spec, plan, subagent build with per-task reviews, PR, CI and merge, with the model of each task type configurable.`
- `.claude-plugin/marketplace.json`: `metadata.description` is
  `amp: a grill-first, autonomous workflow plugin for Claude Code.`; the plugin entry's description
  is `Grill-first, autonomous workflow for Claude Code, with configurable models per task type.`

## 6. States and errors

- A ledger with no `Off:` line (an older run, or a standalone amp:build) shows
  `Steps off: not recorded (the CLAUDE.md table applies)`.
- A user who still has the Codex install: nothing in this repo serves it any more; the changelog
  entry says to stay on 1.6.0. No migration code.
- `scripts/test` fails loudly if any deleted tree reappears or a Codex mention returns.

## 7. Testing strategy

- `bash scripts/test`: the kept text cases and the new `claude-only` case.
- `claude plugin test .`: `hooks/run.test.ts` gains parse tests for `Off:` (names, `none`, absent,
  last line wins); `hooks/run-hooks.test.ts` (which mounts the run pane) asserts the
  `Steps off:` line for a ledger with steps off, with `Off: none`, and with no `Off:` line.
- No renderer check remains.
